## 7. 风险、坑与失败经验

- [R-001] [P0] [已确认] 旧会话因「超大上下文 + 跨境中转」彻底卡死：17:12 起所有请求在网络层失败，界面表现为「发出消息后长时间无任何输出」，实际是在 2~7 分钟一次地重试、最多 5 次。
  - 触发条件：单轮请求体极大（该会话 `input_tokens ≈ 667,507`，模型上下文窗口 950,000）+ 中转链路不稳定。
  - 影响：该会话无法产生任何回复；继续向它发消息只会重复失败（本会话实测：18:42:37 发出的回合仍在 18:42:28/18:42:53 报同样的网络错误）。
  - 规避方式：不要在旧会话继续；把上下文压缩到本文件，在新会话继续。
  - 已尝试方案：直接发送消息（失败）；核对本地代理与日志（确认代理正常、瓶颈在请求体/链路）。
  - 当前结论：旧会话放弃使用（建议归档）。
  - 来源：[S-008]（日志原文）、[S-009]（rollout token 统计与回合状态）、[S-004]（本会话排查）

- [R-002] [P0] [已确认] 宽泛暂存会被风险审查拒绝：`git add -A` 会把约 21 张任务栏截图/对比图一并提交并推送到公开仓库（涉及用户机器状态隐私）。
  - 触发条件：工作区存在测试截图等未跟踪敏感文件时执行 `git add -A` 或 `git commit -a`。
  - 影响：操作被系统拒绝，流程中断；若绕过则泄露用户隐私。
  - 规避方式：先清理测试产物（[C-005]），再按显式路径 `git add <path>...`。
  - 已尝试方案：一次被拒绝后改为显式路径暂存，成功提交 `7d4c733`。
  - 当前结论：永久遵循显式路径暂存。
  - 来源：[S-008]（错误原文）、[S-002]（旧会话 13:48 回复）

- [R-003] [P1] [已确认] 解析外部 CLI 输出的历史缺陷：千位分隔符会把 `210,726,629,888` 截断成 `210`，导致速度与命中率全错（v1.2.1 已修复并加用例覆盖）。
  - 触发条件：`rxpcc` 输出带千位分隔符或系统区域设置变化。
  - 影响：数值严重错误且不易察觉。
  - 规避方式：解析器必须剔除分隔符并覆盖边界用例（现为 7/7 用例）。
  - 来源：[S-002]（旧会话 15:36 回复）

- [R-004] [P1] [已确认] 历史崩溃：首次提权测试退出码 `0xC0000409`（fastfail），原因是采样线程在单例析构时仍 joinable，`std::thread` 析构触发终止（v1.2 已修）。
  - 触发条件：DLL 卸载时后台线程未 join/detach。
  - 规避方式：单例析构必须正确处理线程生命周期（现实现有 `RequestStop()`）。
  - 来源：[S-002]（旧会话 08:01 回复）

- [R-005] [P1] [已确认] 部署坑：DLL 被正在运行的 TrafficMonitor 占用时无法覆盖；主程序关闭按钮只是收进托盘，必须真正结束进程（旧版本曾用强制结束 + 重启完成部署）。
  - 影响：部署失败或误判「已更新」。
  - 规避方式：先退出主程序（含托盘），再替换 DLL，重启后用哈希与「DLL 被锁定」验证已加载。
  - 来源：[S-002]（旧会话 06:44 回复）

- [R-006] [P1] [已确认] 升级坑：`plugins` 目录里同时存在旧的 `taskbardynamic.dll` 与新的 `taskbardynamic-x64.dll` 会导致显示项重复加载。
  - 规避方式：升级前先删除旧文件名，README 已写明。
  - 来源：[S-002]（旧会话 07:18 回复）、[S-005]（README 安装说明）

- [R-007] [P2] [已确认] 测试方法坑：写完文件立刻读会命中 Windows 系统文件缓存，读请求根本没到卷，PrimoCache 统计全为 0 → 必须用 `FILE_FLAG_NO_BUFFERING` 无缓冲读才能验证命中率。
  - 来源：[S-002]（旧会话 13:03 回复）

- [R-008] [P2] [已确认] 体验风险（未完全解决）：窗口样本过小或空闲后首次读取会让命中率从 `--` 突跳到 0% / 100%（方案 A 已缓解，B4-b 门槛未定，见 [Q-003]）。
  - 来源：[S-002]（旧会话 15:44、17:04 回复）

  - 被替代关系：相关改动已入库；用户于本轮开始前恢复工作区，当前新构建尚未部署/发布，见 [F-021]/[A-007]。

- [R-010] [P2] [已确认] 上下文风险：本项目主会话历史极长（rollout 文件 9.9MB + 12.5MB），继续在旧会话里做任何事都会因上下文过大而失败；后续必须在干净会话中工作，并以本文件为唯一入口。
  - 来源：[S-009]、[S-008]

- [R-011] [P1] [已确认] 当前 Codex shell 的进程环境同时包含 `PATH` 与 `Path`，MSBuild 创建 `CL.exe` 时出现 `MSB6001: 已添加项。字典中的关键字:"PATH"所添加的关键字:"Path"`。
  - 影响：无法在该 shell 直接完成构建验证。
  - 规避方式：构造只保留一个去重 `Path` 的干净子进程，再调用 VS2022 `VsDevCmd.bat` 与 `msbuild.exe`；本轮四个配置均由此通过。
  - 来源：本轮构建命令输出（[S-014]）

- [R-012] [P1] [待确认] `rxpcc` 文本解析失败语义不足：缺失/非法 `Cached Read` 或非法 `Total Read` 仍可能被当成成功并返回 0，数值运算也无溢出检查。
  - 影响：显示错误的速度或命中率，且不易察觉。
  - 建议：解析函数返回明确成功标志，检查缺失字段、非法字符、乘加溢出；异常输出直接让采样失败。
  - 来源：当前源码审计（[S-013]）

- [R-013] [P1] [待确认] `HitRateWindow` 名称为 30 秒窗口，但实际按“最近 6 次成功采样”滚动；采样失败、系统调度或长间隔时，窗口覆盖时间可能明显超过 30 秒，卷拓扑变化时旧样本也可能残留。
  - 影响：命中率恢复速度与文档语义不一致。
  - 建议：记录每段实际时间，超时样本淘汰/长间隔重置，并明确多卷聚合语义。
  - 来源：当前源码审计（[S-013]）

- [R-014] [P1] [待确认] `RunCommand` 没有输出上限与退出码检查，超时仅终止直接子进程，且未绑定 Job Object；若 `rxpcc` 派生后代并保持管道写端，结束阶段的同步 `ReadFile` 仍可能阻塞。
  - 影响：异常版本/被替换的 CLI 可能造成内存增长、误采或线程卡住。
  - 建议：限制累计输出大小，检查退出码，用 Job Object `KILL_ON_JOB_CLOSE` 管理进程树，必要时改用可超时 I/O。
  - 来源：当前源码审计（[S-013]）
