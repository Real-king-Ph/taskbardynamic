## 2. 不可违背的约束

- [C-001] [P0] [已确认] 显示项是否显示由用户自己控制：插件只负责注册显示项，不得替用户改勾选状态。
  - 来源：用户原话（旧会话 07:48 本地「3. 是否显示由我自己控制」）[S-001]
  - 适用范围：所有插件改动、配置操作
  - 违反后果：与用户明确要求冲突（用户多次强调「本地修改我怕自己来」）

- [C-002] [P0] [已确认] 不要修改用户的 `C:\tool\TrafficMonitor\config.ini`（由用户自己改）。
  - 来源：用户原话（旧会话 13:04「插件默认这些选项都不是开启的。本地修改我怕自己来」）+ 助手回复「未动你的 config.ini（按你的要求）」[S-001]/[S-002]
  - 违反后果：破坏用户本地环境与既有设置

- [C-003] [P0] [已确认] 需要用户手动批准 / UAC 的操作必须先停下等用户；用户休息期间不得执行。
  - 来源：用户原话（旧会话 16:37「后续如果需要我手动UAC的操作先不要进行，我要睡觉去了，等我回来再统一执行需要我手操的任务」）[S-001]
  - 违反后果：打断用户、产生无人值守的高权限操作

- [C-004] [P0] [已确认] 禁止宽泛暂存（如 `git add -A`）：会把任务栏截图等敏感文件一起提交；必须按显式路径暂存。

  - 违反后果：把用户机器状态截图推送到公开仓库（隐私泄露），并被系统拦截导致流程失败

- [C-005] [P0] [已确认] 提交前必须清理测试过程中产生的不需要的文件（截图、`NEXT-STEPS.md` 等）。
  - 来源：用户原话（旧会话 13:32「记得把测试过程中产生的不需要commit 的所有文件删除，包括NEXT-STEPS」）[S-001]

- [C-006] [P0] [已确认] 发布前的固定顺序：先按序执行改动 → 发布前做一次代码检查（含漏洞检查）→ 若有问题则修复后重复前述步骤 → 才允许发布。
