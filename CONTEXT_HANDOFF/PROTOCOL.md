# Context Handoff Protocol

> 适用项目：`D:\coding\taskbardynamic`
> 入口：`AGENTS.md` 自动触发 -> `PROTOCOL.md` -> `00_INDEX.md` -> 按需加载分域文件
> 最后更新：2026-09-23
> 目标：让每个新对话自动接续上下文，同时避免单个 HANDOFF 文件继续膨胀。

## 1. 权威层级

1. 用户当前明确指令优先级最高。
2. `01_GOALS_CONSTRAINTS.md` 中的 P0 约束必须遵守。
3. `03_DECISIONS_OPEN_ISSUES.md` 中的有效决策和冲突处理优先于推断。
4. `[已确认]` 可视为事实；`[推断]` 和 `[待确认]` 使用前必须核实。
5. `[已废弃]` 仅用于追溯，不得作为当前执行依据。

## 2. 每次任务开始时

1. 读取 `PROTOCOL.md` 和 `00_INDEX.md`。
2. 根据本文件与索引，只加载当前任务相关的 2~4 个内容文件。
3. 确认当前目标、P0 约束、当前状态、阻塞和下一步。
4. 如需历史细节，通过 `08_TIMELINE_SOURCES.md` 的来源 ID 回查。
5. 如果当前指令与 HANDOFF 冲突，以用户当前指令为准，并记录冲突。

## 3. 工作过程中

- 目标、硬约束、事实、决策、状态、产物、风险或行动变化时，立即更新权威文件。
- 新条目使用稳定 ID，并在来源中写明用户原话、文件、命令、时间或来源 ID。
- 同一信息只能有一个权威存放位置；其他地方使用 ID 引用。
- 不得静默删除、覆盖或合并存在冲突的信息。
- 不把业务代码、大段日志或完整历史复制进 HANDOFF；保留结论、必要原文和来源指针。

## 4. 每次任务结束前

1. 更新受影响的权威文件。
2. 追加时间线；如有新来源，补充来源索引。
3. 更新 `00_INDEX.md` 的快速状态、阻塞、下一步和更新时间。
4. 更新 `10_AUDIT.md` 的日期、范围和完整性结论。
5. 运行完整性检查：目标、P0、事实、决策、问题、风险、产物、进度、下一步是否仍可找到。
6. 报告修改了哪些 HANDOFF 文件；不得声称修改了实际未修改的文件。

## 5. 状态与字段

优先级：

- P0：必须遵守，违反会导致任务失败、数据泄漏或用户环境受损。
- P1：重要，影响方案、结果或发布质量。
- P2：背景信息，可在空间紧张时延后加载。

状态：

- `[已确认]`：有明确依据或用户确认。
- `[推断]`：Codex 根据上下文推断，尚未确认。
- `[待确认]`：需要用户、代码或外部系统验证。
- `[冲突]`：存在两个及以上相互矛盾的来源。
- `[已废弃]`：历史有效但已被替代；必须注明替代项。
- `[已完成]`：行动项已经完成并经过验收。

每个重要条目至少包含：ID、优先级、状态、正文、来源。行动项还必须包含目标、依赖、验收条件和风险。

## 7. 拆分阈值

- `00_INDEX.md`：建议 500~1,500 tokens，约 30~100 行，绝不放正文长文。
- 单个内容文件：建议 2,000~5,000 tokens，约 100~250 行。
- 单文件达到 6,000 tokens 或 300 行：评估拆分。
- 单文件超过 8,000~10,000 tokens 或 500 行：必须拆分。
- 顶级章节超过 10~12 个：优先拆分。
- 新任务通常只需要读取总量 50% 以下时：拆分收益明显。
- 新任务每次都必须读取 80% 以上时：不要为了拆分而制造更多跳转。
- 总量超过 20,000 tokens：必须使用索引和选择性加载。
- 总量超过 50,000 tokens：应转为可检索知识库，不再作为单次 HANDOFF 全量加载。

拆分时必须：

1. 保持稳定 ID 不变。
2. 同步更新 `00_INDEX.md` 的文件地图和旧章节映射。
3. 不产生孤立文件。
4. 不复制正文；跨文件只引用 ID 或链接。
5. 在 `10_AUDIT.md` 记录拆分原因、前后规模、缺失检查和删除的旧文件；默认不保留重复归档，除非用户明确要求。

## 8. 索引维护

`00_INDEX.md` 只包含：

- 当前主目标、当前状态、当前阻塞、下一步。
- P0 快速摘要。
- 阅读顺序。
- 文件地图与 ID 权威位置。
- 旧章节映射。
- 更新规则。

不得把全文复制进索引。索引更新必须与内容更新同一次任务完成。

## 9. 维护与审计清单

每次维护后检查：

- 每个 G / C / U / F / D / Q / R / A / T / S / X 条目是否有唯一权威位置。
- 所有 P0 约束是否仍存在且未被错误改写。
- 所有未解决问题是否有状态、阻塞和下一步。
- 所有关键产物是否有路径、版本或哈希。
- 所有被替代决策是否标记 `[已废弃]` 并指向替代项。
- 所有冲突是否保留双方来源。
- `00_INDEX.md` 是否能够路由全部内容。
- 是否存在超过阈值但未拆分的文件。
- 是否存在缺失引用、重复正文或孤立文件。
- 原始来源索引是否仍足以回查。

## 10. 安全与提交约束

- 禁止 `git add -A`；只按显式路径暂存。
- 未获用户明确同意前，不提交、不发布、不部署。
- 不修改 `C:\tool\TrafficMonitor\config.ini`。
- 需要 UAC 或用户手动批准的操作必须等待用户。
- 如果 HANDOFF 内容包含敏感信息，提交前先确认是否应加入 `.gitignore`。
